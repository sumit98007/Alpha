ALPHA PRIVACY NOTICE

Know what leaves your device.

On first use, Alpha asks before it reads or transmits composer text. Recent-chat sharing requires its own confirmation before Alpha reads recent visible messages. After you save those choices, each later bubble click is the explicit action that reads and sends that request until you reset your privacy choices.

What Alpha processes

  • The prompt you choose to refine.
  • Up to 8 recent visible chat messages, capped at 12,000 characters, only when “Use current chat” is enabled and separately allowed.
  • Your optional prompt preferences and custom guidance.
  • The supported host-platform identifier: ChatGPT, Claude, or Gemini.

Where processing happens

Alpha applies selected sensitive-value detection and redaction locally when protection is enabled. The resulting text—which can still contain sensitive data when protection is off or detection misses a value—is sent over HTTPS to Alpha’s gateway and then to Google Gemini for the sole purpose of producing a refined prompt. The gateway also receives placeholder metadata needed to enforce integrity: whether a placeholder came from the prompt, recent chat, or guidance, a request identifier, and the number of occurrences. When local protection is enabled and detection succeeds, this metadata never contains the detected-value category, detected value, or Alpha’s local placeholder-to-value map; those remain on this device.

That local protection applies only to Alpha’s refinement path. The AI website owns and controls its composer and page, so it may already observe or process text you type there under its own terms, including before you submit it.

Limits of local protection

Alpha recognises specific patterns such as supported API keys, credentialed database URLs, validated payment-card numbers, and selected government identifiers. Automated detection is not complete and may miss names, addresses, private business information, source code, passwords, or an unfamiliar secret format. Review content before refining it.

Restored values and the target AI service

Prompt-owned protected values are restored locally only after strict placeholder-integrity checks pass; otherwise Alpha falls back to the unchanged original prompt. When you choose “Use prompt,” the result is inserted into the current AI service’s composer. The host service controls that composer and may observe or process the result, including restored values, before submission under its own privacy terms. Alpha’s local protection does not hide drafts or inserted results from the host page. Values detected only in recent chat or guidance are never restored into the refined prompt.

When you choose “Copy,” Alpha writes the complete result—including any restored prompt-owned values—to the system clipboard. Other applications, operating-system features, or clipboard managers may be able to access clipboard contents.

Storage and retention

After a successful refinement, the base prompt and matching refined result remain only in the current tab’s extension-owned frame memory so the bubble can reopen the result and “Try again” can use the same base. The matching cache key is a SHA-256 fingerprint; it does not contain raw prompt or recent-chat text. The base and result are not written to persistent Chrome storage. A failed or cancelled refinement clears the retry base, and reloading or closing the tab clears all of this page memory. Alpha stores preferences, consent records, the bubble position, aggregate protection/refinement counters, and custom guidance in Chrome’s local extension storage until you overwrite them, choose “Clear saved data,” or remove the extension. Custom guidance is not redacted at rest, so do not save secrets there. Clearing saved data does not sign you out; use Sign out separately to remove the in-memory session token. Alpha’s API is designed not to persist prompt or recent-chat content; security and reliability metadata must not include that content.

Abuse, rate, and quota controls

Alpha’s gateway processes the connection source IP and the authenticated JWT subject to enforce abuse controls, request rates, and account quotas. Production disables default raw-IP request logging. Redis limiter keys use secret-keyed HMAC identifiers rather than raw IP addresses or subjects, and retain counters only for their fixed window: 60 seconds for rate limits and up to 24 hours for the daily quota. Prompts, recent chat, access tokens, and raw identifiers are not written to application logs or limiter keys.

Sign-in session

Alpha signs in through your configured identity provider using Authorization Code with PKCE. The extension has no client secret, never accepts tokens in a redirect URL, requests no refresh token, and keeps the short-lived access token only in Chrome’s in-memory session storage for no more than one hour. Signing out or closing the browser session removes the local copy; provider-side validity of an already issued token ends at expiry, within one hour.

Chrome Web Store Limited Use

Alpha’s use of information received from Google APIs adheres to the Chrome Web Store User Data Policy, including the Limited Use requirements. Prompt and optional recent-chat data are used only to provide Alpha’s disclosed prompt-refinement purpose. Alpha does not sell user data or use it for advertising, lending, or credit-worthiness. Humans do not routinely read prompt or chat data; access is allowed only with specific consent, for security or abuse investigation, or where legally required.

Your controls

Turn Alpha off, disable recent-chat context, reset privacy choices, or clear persistent local extension data from the Alpha menu. Resetting choices makes Alpha ask again before reading or transmitting another prompt. Turning sensitive-value protection off also resets the sharing choices so the changed protection state is disclosed before another refinement.
